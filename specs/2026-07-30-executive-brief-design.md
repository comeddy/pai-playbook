# 경영진 브리핑 + 임원 대화 가이드 — 설계

날짜: 2026-07-30 · 승인: Youngjin (브레인스토밍 Q1~Q6 + §1~§3 섹션별 승인)

## 배경·목적

플레이북은 현재 전부 SA(기술) 독자용이다. 비즈니스/C-level 면을 연다:
**임원이 직접 읽는 페이지**(경영진 브리핑) + **SA가 임원 미팅에 쓰는 가이드**(임원 대화 가이드) 세트.

확정 선택지:

| 질문 | 결정 |
|---|---|
| 사용 장면 | C — 임원용 읽기 페이지 + SA용 대화 가이드 세트 |
| 배치 | A — 사이트 상단 탭 2개 (별도 랜딩 아님) |
| 임원 페이지 CTA | C — 판단 프레임 제공 + 마지막 "첫 걸음" CTA |
| 가이드 구성 | 전부 — 피치·Top10 Q&A·반박 대응·산업 앵글·금지 표현 |
| 언어 | A — 4개 언어 전부 (ko 원본 + en/zh/ja 동기화) |
| 수치·주장 톤 | A — 검증 톤 유지 (전망치는 출처·성격을 문장 안에 명시) |
| 페이지 구조 | 접근 1+2 하이브리드 — "임원의 5가지 질문" 흐름 + 중심에 "지금/곧/아직" 판단 매트릭스 |

## 페이지 1 — 경영진 브리핑 (`docs/exec.md`)

임원이 5분 안에 "균형 잡힌 판단 프레임 + 첫 걸음"을 얻는 단일 페이지.
**과장 없는 브리핑 자체가 차별점** — 컨설팅사 자료와 정반대 포지션.

구조 (5가지 질문 흐름):

1. **머리말 (L0 TL;DR 관례)** — 3문장: 변곡점이다 / 단, 지금 할 것과 지켜볼 것은 다르다 / 이 페이지가 그 구분을 제공한다.
2. **① 왜 지금인가** — 검증된 변곡점 신호 3개 (Figure 02@BMW 검증 파일럿, Agility 9개 현장 6.5만 시간, 오픈 파운데이션 모델 등장). 시장 전망치는 1문장, "○○ 추정, 2035년 전망" 식으로 성격 명시.
3. **② 우리 산업에 무슨 의미인가** — 제조/물류/자동차 3개 산업 × 2문장 (무엇이 바뀌나 + 선행 기업은 무엇을 하나).
4. **③ 뭐가 진짜고 뭐가 과장인가 — 판단 매트릭스** (페이지의 심장):
   - 🟢 지금 투자 (검증된 기반 역량): 로봇 데이터 파이프라인, 시뮬레이션 인프라, 합성 데이터
   - 🟡 곧, 12~24개월 (파일럿 가치): VLA 파인튜닝 역량, 엣지 추론 스택, 에이전트 오케스트레이션
   - ⚪ 아직 (관찰 대상): 휴머노이드 대규모 도입, 완전 자율 시프트
   - 각 셀은 기존 pillar/radar의 **검증된 판정만 인용** — 새 주장 없음.
5. **④ 그래서 무엇부터 하나** — "데이터부터"라는 정직한 답 + 3단계 로드맵 (파이프라인 → 시뮬 PoC → 파인튜닝 파일럿).
6. **⑤ 왜 AWS와 하나** — 검증된 사실만: HyperPod 실사례(Unitree H1), 서울 리전 AgentCore GA, 오픈 모델 셀프호스팅 자유.
7. **CTA** — "1일 아키텍처 워크숍 (데이터 자산 진단 + 판단 매트릭스를 귀사 상황에 적용)" + SA 연락 동선.

분량 ~1,800자 (임원 5분). 기술 딥링크는 하단에 모음 (본문 중 최소화).
메타데이터: owner Youngjin · volatility 중간(3개월) — 매트릭스 항목은 radar 승격/강등 시 갱신.

## 페이지 2 — 임원 대화 가이드 (`docs/exec-guide.md`)

SA가 임원 미팅 30분 전에 훑는 실전 자산. Brief가 "보여주는 것", 가이드는 "말하는 법".

구조:

1. **엘리베이터 피치 3종** — 30초(한 문단) / 2분(불릿 5개) / 5분(Brief를 화면에 띄우고 걷는 순서). 각각 "쓰는 장면" 한 줄.
2. **예상 질문 Top 10 + 답변 스크립트** — "ROI 나오나?", "NVIDIA랑 뭐가 다른가/왜 AWS인가?", "경쟁사는?", "우리가 늦었나?" 등. 답변 3~4문장 + 근거 pillar/radar 딥링크. index FAQ Top 20 형식 관례.
3. **반박·우려 대응 5개 내외** — "휴머노이드 아직 데모 아닌가?", "안전·규제는?", "인력 대체는?" 등. **인정 → 프레임 전환 → 검증된 다음 걸음** 3박자 구조 명시.
4. **산업별 앵글 표** — 제조/물류/자동차 3개 확정: 훅 한 줄 + 검증 사례 한 줄 + 첫 제안 아이템. (유통은 작성 시점에 검증된 사례가 있을 때만 추가 — 사례 없는 산업 행 금지)
5. **⚠️ 금지·주의 표현** — radar 원칙의 임원 미팅 버전. ❌/⭕ 예시 표 (❌ "옵티머스 곧 양산" → ⭕ "휴머노이드는 검증 파일럿 단계, 저희는 그 전 단계인 데이터·시뮬 인프라 제안"). radar.md 딥링크.

분량 ~2,500자. 메타데이터: owner Youngjin · volatility 중간.

## 구현·유지보수

- **nav**: "가이드" 다음, P1 앞에 "경영진 브리핑" · "임원 대화 가이드" 삽입. `nav_translations` en/zh/ja 추가.
- **4개 언어**: ko 작성 → translate-sync → ko_hash 편입. 동기화 기대값 30→**36쌍**. radar 스캔 루틴 프롬프트의 "비동기: 0/30" 기대값도 **0/36으로 갱신** (0/27→0/30 정정과 같은 유형의 후속 조치).
- **게이트**: strict 빌드 · 외부 링크 curl 200 · staleness 메타데이터 필수 — 기존 그대로.
- **콘텐츠 원칙 (신규 규칙)**: 두 페이지는 **새로운 기술 주장 금지** — 기존 pillar/radar 검증 판정의 "임원 언어 번역"만. maintenance.md에 한 줄 명문화해 향후 갱신자도 준수.
- **충돌 회피**: 신규 파일 2개(×4개 언어) + mkdocs.yml nav 훅크만 변경. 다른 세션이 작업 중인 pillar 파일들은 건드리지 않음. mkdocs.yml은 해당 훅크만 선택 스테이징.
- **CHANGELOG**: Unreleased에 기록.

## 범위 밖 (YAGNI)

- 별도 랜딩 디자인(`/exec/` HTML) — 탭 방식 확정으로 불필요.
- PDF/인쇄 버전, 산업별 개별 페이지, 임원용 오프라인 자료 — 요청 시 별도.
- 시장 수치 자동 갱신 — 전망치는 최소 인용이라 수동 관리로 충분.
