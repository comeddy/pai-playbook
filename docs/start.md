# 시작 — 업무 적합성·ROI·파일럿 승인

_최종 갱신: 2026-11 · owner: Youngjin · volatility: 중간_

**L0 TL;DR**: 기술보다 업무가 먼저다. 어떤 업무를 개선하고 싶은지, 지금은 얼마나 잘하고 있는지부터 적어 보자. 그다음 기존 자동화·상용 제품·SI[^si]로 풀 수 있는지 따져 본다. 그래도 로봇이 새로 배워야 할 부분이 남을 때만 데이터·시뮬레이션·VLA를 검토하면 된다. 이 페이지는 고객과 AWS 직원이 함께 채워 가는 판단 양식이다.

## 역할별 경로 { #roles }

| 역할 | 먼저 볼 것 | 회의에서 남길 결과 |
|---|---|---|
| 고객 의사결정자 | 이 페이지 → [경영진 브리핑](exec.md) | 업무 1개, 비용 상한, 추진·보류 기준 |
| 고객 기술팀 | [실행 경로](execution.md) → 해당 필러 → [운영·복구](operations.md) | 준비물, 실험 계획, 책임자 |
| AWS 직원 | [대화 가이드](exec-guide.md) → [의사결정](decisions.md) | 발견 질문, 대안 비교, 지원·파트너 역할 |

직원용 가이드도 공개 문서다. 내부 연락처·고객 비공개 자료는 이 사이트에 기록하지 않는다.

## 업무 적합성 — 첫 미팅 8문항 { #fit }

| 질문 | 고객과 채울 내용 |
|---|---|
| 무슨 업무를 개선하나? | 공정·물체·환경·작업 시작/완료 조건을 한 문장으로 |
| 지금 얼마나 잘하나? | 시간당 완료량, 작업 시간, 실패·재작업률, 사람 개입 횟수 |
| 왜 기존 방식으로 부족한가? | 규칙 기반 자동화, 기존 제어 개선, 상용 제품, SI 견적 비교 |
| 학습이 필요한 변화는 무엇인가? | 물체·조명·배치·언어 지시 변화와 실제 발생 빈도 |
| 무엇을 이미 갖고 있나? | 로봇·센서·로그·데모·CAD, 사용 권리, 담당 인력 |
| 현장 제약은 무엇인가? | 사람 접근, 통신 단절, 지연, 전력, 데이터 처리 국가 |
| 누가 운영하고 복구하나? | 현장 운영자·로봇/SI·ML·클라우드 담당자 실명 |
| 무엇이면 중단하나? | 비용·기간 상한, 기준 방식 대비 최소 개선, 안전·복구 조건 |

**추진**: 업무와 기준선이 측정 가능하고, 기존 대안보다 개선할 가설·실험 자원·운영 책임자가 있다. **보류**: 데이터 권리, 현장 책임, 비용 상한 중 하나가 미정이다. **대안 선택**: 상용 제품이나 기존 자동화가 요구를 더 낮은 총비용으로 충족한다. [Build vs Buy](decisions.md#4-build-vs-buy-파운데이션-모델)에서 선택을 기록한다.

## 총비용과 ROI — GPU 견적만으로 판단하지 않는다 { #roi }

아래 항목을 **낮음/기준/높음 시나리오**로 계산한다. 미확인 비용을 0으로 넣지 말고 ‘견적 대기’로 둔다. 아래 계산기에 수량·단가·기간을 바로 입력하면 결과가 즉시 계산되고, 입력값과 결과를 CSV로 내려받아 프로젝트 문서에 첨부할 수 있다(USD 예시 양식, 가격표 아님).

| 비용 구분 | 포함할 항목 |
|---|---|
| 초기 고정비 | 로봇·그리퍼·센서, 설치·SI, 데이터 수집·정제, 환경 제작, 안전 검토·검증 |
| 실험 변동비 | GPU 인스턴스 시간, 스토리지·전송·로그, 모델/API, 실패 실행·재시도, 실험 인력 |
| 운영 반복비 | 유지보수·부품·관제, 사람 개입, 추론·연결, 재학습·현장 재검증 |
| 기대 효과 | 실제 감소한 재작업·정지 시간, 처리량 증가의 실현 가능한 가치, 재배치 가능한 인력 시간 |

| 지표 | 계산 방법 | 읽는 법 |
|---|---|---|
| **초기 투자** | 초기 고정비 + 실험 변동비 | 파일럿을 시작해 검증을 마칠 때까지 한 번 드는 돈 |
| **기간 운영비** | 월 운영 반복비 × 기간(개월) | 분석 기간 동안 계속 나가는 돈 |
| **기간 효과** | 월 기대 효과 × 기간(개월) | 분석 기간 동안 실제로 얻는 가치 |
| **기간 순편익** | 기간 효과 − 기간 운영비 | 운영하면서 남는 돈 — 초기 투자는 빼지 않은 값 |
| **회수 기간** | 초기 투자 ÷ 월 순편익 | 초기 투자를 되찾는 데 걸리는 개월 수. 월 순편익(월 효과 − 월 운영비)이 0 이하이면 ‘회수 불가’ |
| **기간 ROI** | (기간 효과 − 초기 투자 − 기간 운영비) ÷ (초기 투자 + 기간 운영비) | 쓴 돈 전체 대비 남는 비율. 0% 미만이면 분석 기간 안에는 손해 |

<div class="pai-roi-calc"><noscript><p>자바스크립트가 꺼져 있으면 계산기가 표시되지 않는다. 위 표의 계산 방법으로 직접 계산한다.</p></noscript></div>

시뮬레이션은 실험비를 줄일 수 있지만 환경 제작·보정·실기 검증 비용을 없애지 않는다. 생산성 증가와 인건비 절감을 같은 효과로 이중 계산하지 않는다. 비용 견적과 효과 가정의 근거·확인일을 함께 기록한다.

## 파일럿 승인 카드 { #pilot }

파일럿을 시작하기 전에 고객과 함께 아래 10개 질문에 답한다. **비어 있는 칸이 있으면 아직 시작할 때가 아니다.** 예시는 이해를 돕기 위한 가상 값이다. 완료 시간·데모 수·성공률은 범용 약속이 아니라 고객과 합의할 값이다.

| # | 항목 | 쉽게 말하면 | 예시 (가상 값) |
|---|---|---|---|
| 1 | 업무 / 제외 범위 | 로봇에게 정확히 무엇을 시키나? 이번에 하지 **않을** 일은? | 혼합 상자에서 부품을 집어 트레이에 놓기. 파손품 처리·야간 근무는 제외 |
| 2 | 현재 방식 / 비교할 대안 / 기준선 측정 기간 | 지금은 어떻게, 얼마나 잘하고 있나? 로봇 말고 다른 해법(기존 자동화·상용 제품)과도 비교하나? 지금 실력을 며칠 동안 재서 비교 기준으로 삼나? | 작업자 2명이 시간당 300개, 오류 2%. 상용 피킹 셀 견적과 비교. 2주간 측정 |
| 3 | 목표 지표 / 최소 개선 / 측정 조건 | 무엇으로 성공을 판단하나? 최소 얼마나 나아져야 의미가 있나? 어떤 조건에서 재나? | 성공률·시간당 처리량. 기준선보다 처리량 20% 이상 개선. 실제 라인 속도·조명에서 측정 |
| 4 | 평가 표본 수 / 반복 실행 / 미학습 환경 | 몇 번 시험하나? 다시 해도 결과가 비슷한가? 학습 때 못 본 물건·배치에서도 되나? | 시도 200회, 3일에 나눠 반복, 학습에 없던 부품 5종 포함 |
| 5 | 데이터·코드·가중치 사용 권리 | 수집한 데이터, 사용한 코드, 학습된 모델 파일(가중치)은 누구 것이고 상업적으로 써도 되나? | 데이터는 고객 소유. 사용할 오픈 모델의 라이선스가 상업 이용을 허용하는지 확인 |
| 6 | 담당자 | 분야마다 책임자를 1명씩 정했나? | 현장 운영 · 로봇/SI · ML · 클라우드 · 안전 담당 각 1명 |
| 7 | 비용 | 처음 드는 돈, 실험 기간에 드는 돈, 운영하면 매달 드는 돈은? 낙관·기준·비관 3개 값으로 | 초기 / 실험 / 월 운영 각각을 낮음·기준·높음으로 기록 |
| 8 | 한도 | 최대 얼마까지, 언제까지 쓰나? 늘리려면 누가 승인하나? | 지출 상한, 종료일, 연장은 사업부장 승인 |
| 9 | 중단 조건 | 어떤 경우에 멈추나? 시작 전에 미리 정해 둔다 | 종료일까지 최소 개선 미달 · 지출 상한 초과 · 비상정지/복구 시험 실패 중 하나라도 해당 |
| 10 | 다음 단계 증거 / 승인자 | 다음 단계로 가려면 무엇을 보여 줘야 하고, 누가 승인하나? | 평가 리포트·비용 실적·안전 점검표 → 공장장 승인 |

아래 블록을 프로젝트 문서로 복사해 채운다.

```text
1. 업무: 로봇이 할 일 / 이번에 제외할 일:
2. 기준선: 지금 방식과 성과 / 비교할 대안 / 측정 기간:
3. 목표: 성공 지표 / 최소 개선 폭 / 측정 조건:
4. 평가: 시험 횟수 / 반복 횟수 / 학습에 없던 환경:
5. 권리: 데이터·코드·모델(가중치)의 소유와 사용 범위:
6. 담당자: 현장 / 로봇·SI / ML / 클라우드 / 안전:
7. 비용(낮음·기준·높음): 초기 / 실험 / 월 운영:
8. 한도: 최대 지출 / 종료일 / 연장 승인자:
9. 중단 조건: 목표 미달 / 비용 초과 / 안전·복구 시험 실패:
10. 다음 단계: 보여 줄 증거 / 승인자:
```

**단계별 통과 조건**: 기준선 확보 → [격리 실험](execution.md) → [제한된 현장 검증](operations.md) → 운영 확대. 각 단계에서 지표·비용·사람 개입·복구 결과를 검토한다. 특정 기술의 GA나 공통 ‘12~24개월’ 전망으로 다음 단계를 승인하지 않는다.

**➡️ 다음 액션**: 다음 고객 미팅에서 이 카드 1장을 채우고 추진·보류·대안 중 하나를 결정한다. 추진이면 [실행 경로 3개](execution.md) 중 현재 병목에 맞는 하나만 선택한다.

<!-- 용어 각주 -->
[^si]: **SI (System Integrator)** — 로봇·설비·제어·소프트웨어를 고객 현장에 맞게 통합하는 사업자. 클라우드 서비스 지원과 현장 셀의 통합·안전 책임은 별도로 정해야 한다.
