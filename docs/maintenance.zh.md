# 维护 — 收录、证据与更新规则

_最后更新: 2026-09 · owner: Youngjin · volatility: 中_

**L0 TL;DR**: 区分相关性、发布状态、证据、用途和支持责任。自动化检查缺失/不一致记录；人负责事实复核和客户现场批准。

## 纳入标准 (THE FILTER)

原“4 项中 2 项”只作为**主题相关性信号**：客户需求、AWS 映射、发布状态、现场案例。映射加路线图不构成验证。

收录须**全部满足**：(1) 客户问题或 R&D 问题，(2) 准确一手来源/日期/版本，(3) 证据、限制、允许用途，(4) owner 和可执行后续行动。数字附条件、样本、单位。未对照一手来源的条目留在 Radar。

研究可用于假设验证型 R&D 指导，不用于运营性能承诺。扩大运营还需[试点卡](start.md#pilot)及[现场条件](operations.md#release)证据。

## 成熟度、来源及用途

| 维度 | 标记 | 解读 |
|---|---|---|
| 发布 | GA / Preview / Research / 不适用 | 按产品；原理、法规、算法不标 GA |
| 证据 | 厂商发布 / 原文对照 / 实验复现 / 客户现场验证 | 不自动推断下一阶段 |
| 用途 | 学习/R&D / PoC 评估 / 运营扩大审查 | 同时记录验证范围及限制 |
| 支持 | AWS 服务 / 模型供应商 / 伙伴-SI / 样本维护者 | 分开支持合同及现场责任 |

`[1]` 官方文档/论文、`[2]` 有记录的复现、`[3]` 厂商发布、`[4]` 未验证是**来源类型**，不是排名或 AWS 官方批准。`[2]` 需要执行者、版本、环境、日志、测量条件。旧 `[2]` 无日志不得作为复现证据。发布不等于 GA，运行一次不等于生产验证。

## 元数据与时效

保留页面 `_owner: 姓名 · updated: YYYY-MM · volatility: 高/中/低_`。日期描述**页面修改/复核范围**，局部修改不刷新其他主张日期。页面徽章按高1/中3/低6个月超期提醒。

影响决策的主张加入[证据记录](evidence.md)。`checked_on` 是原文对照日，`review_after_days` 是逐项周期，`pages` 列出受影响摘要及支柱。旧有未迁移主张明确留在记录范围之外。

## 标准模板

```text
条目 / 客户问题:
发布 / 证据等级 / 用途 / 支持方:
L0: 是什么、适用条件:
替代方案 / AWS 映射及前提:
证据 ID / 准确来源 URL / 版本 / 日期:
实验: 环境、样本、单位、日志 / 复现者:
限制 / 费用、成功、停止条件:
后续行动 / 执行资产 / 运营交接:
owner / 人工复核人或待定:
```

L0 保持简短，细节折叠或链接。难词首次加 `[^term]`，末尾 `<!-- 용어 각주 -->` 下写1~2句定义。翻译保留脚注 ID、URL、结构。高管摘要不能删去支柱条件及限制。公开页不放内部客户资料及销售策略。

## Playbook 晋升管道

1. 在 Radar 或候选表记录主题、来源、客户问题。
2. owner 核对全部条件并分配专业复核，扫描不能自动晋升。
3. 对照证据、版本、日期、测量条件，明确 R&D/PoC/现场范围。
4. 同步更新韩语原文、受影响摘要和 en/zh/ja。
5. 生成证据显示、同步哈希、检查、复核后合并。

## 角色与待完成复核

| 角色 | 责任 |
|---|---|
| owner Youngjin | 分配复核、决定收录、管理更新 |
| 人工专业复核人 — 待分配 | 许可证 / AWS 服务区域 / 机器人安全 / 实验复现 |

一个 owner 不解决复核瓶颈。专业人员接受任务后再记录姓名。区分自动对照和人工批准，不虚构复核人。

## 检查及限制

```bash
python3 scripts/check_evidence.py
python3 scripts/check_translation_sync.py
python3 scripts/check_nav_index_sync.py
python3 scripts/check_staleness.py --check
mkdocs build --strict
```

证据结构/显示错误、nav 不一致、元数据缺失、内部文档链接/锚点错误阻断部署。逾期及人工待复核会报告；当前 CI 对翻译漂移仅警告。提交前另行要求**翻译不一致为零**。构建不验证外链可达、事实、翻译含义或机器人执行。
