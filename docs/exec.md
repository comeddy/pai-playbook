# 경영진 브리핑 — 업무 가치와 투자 승인

_최종 갱신: 2026-09 · owner: Youngjin · volatility: 중간_

**L0 TL;DR**: 개선할 업무 하나를 정하고 기존 자동화·상용 제품과 비교한다. 제한된 실험에서 효과·총비용·운영 가능성을 확인한 뒤 투자 범위를 넓힌다.

## ① 왜 지금인가

공개 모델과 시뮬레이션·학습 자산을 검토할 수 있지만, 제품 공개나 서비스 GA가 고객 업무의 수익성을 보장하지는 않는다. [기술 선택](pillar-2.md), [실행 경로](execution.md), [근거 기록](evidence.md)을 연결해 우리 환경에서 시험할 가설을 만든다.

## ② 우리 산업에는 무슨 의미인가

| 업무 예시 | 먼저 측정할 것 | 비교할 대안 |
|---|---|---|
| 제조 검사·부품 취급 | 불량·재작업, 주기, 사람 개입 | 기존 비전·제어 개선, 상용 셀, SI |
| 물류 이동·적재 | 처리량, 정지·복구 시간, 작업 환경 변화 | 기존 AMR/플릿 제품, 운영 절차 개선 |
| 로봇 제품 개발 | 데이터 준비·학습·평가 시간, 실기 실패 | 기존 개발 환경 개선, 클라우드 실험 |

위 표는 발견 질문용 예시다. 특정 모델이나 휴머노이드 도입을 모든 업무의 기본 해법으로 정하지 않는다.

## ③ 무엇이 진짜이고 무엇이 과장인가

| 판단 | 필요한 조건 | 결정 |
|---|---|---|
| 제한 실험 추진 | 측정 가능한 기준선, 사용 권리, 책임자, 예산 상한 | [파일럿 카드](start.md#pilot) 승인 |
| 현장 파일럿 추진 | 분리 평가에서 개선, 지연·안전·복구 시험 계획 | 감독하에 범위 제한 |
| 운영 확대 | 현장 성과, 실제 운영비, 개입·복구 결과, 지원 책임 | 단계적으로 확대 |
| 보류·대안 | 권리·안전 책임 미정, 기존 대안이 더 경제적, 반복 목표 미달 | 원인 해소 또는 다른 방식 선택 |

‘GA라 지금 투자’, ‘12~24개월 후 성과’라는 공통 시간표를 쓰지 않는다. 제품 출시, 실험 재현, 고객 현장 검증을 분리한다.

## ④ 그래서 무엇부터 하는가

[업무 적합성 8문항](start.md#fit)을 채우고 기준 방식과 비교한다. 학습이 필요하다면 현재 병목에 맞춰 데이터 수집, 시뮬레이션, 파인튜닝 중 하나를 선택한다. 준비 단계의 기간과 학습 실행 시간을 구분한다.

**ROI는 총비용으로 계산한다.** 로봇·통합·데이터·인력·안전 검증의 초기 비용과 유지보수·개입·클라우드의 운영 비용을 포함한다. 낮음/기준/높음 시나리오에서 회수 기간을 확인한다. [ROI 양식](start.md#roi).

## ⑤ 왜 AWS와 하는가

고객의 기존 AWS 데이터·보안·운영 환경을 재사용할 수 있는지 검토하고, 작게 실측한 뒤 필요한 서비스만 추가한다. 단일 GPU 실험, 관리형 학습, 멀티노드 학습의 선택 조건은 [의사결정](decisions.md)에 있다. 클라우드 지원, 모델 공급자 지원, 로봇/SI의 현장 책임을 따로 정한다.

서울 리전 지원만으로 국내 데이터 처리를 보장하지 않는다([AgentCore 근거](evidence.md#agentcore-residency)). 오픈 코드 라이선스만으로 가중치의 상용 권리를 보장하지 않는다([OpenVLA 근거](evidence.md#openvla-license)). 이전보다 이동이 쉬운 구성인지 평가하되 ‘락인 없음’을 약속하지 않는다.

## 검토를 시작한다면

업무 책임자·기술팀·AWS 담당이 [파일럿 승인 카드](start.md#pilot)를 작성한다. 산출물은 **업무 1개, 비교 기준, 비용·기간 상한, 운영/안전 책임자, 성공·중단 조건**이다. 이후 [실행 경로](execution.md)와 [운영·복구 게이트](operations.md#release)로 연결한다.
