# 経営層ブリーフィング — 業務価値と投資承認

_最終更新: 2026-09 · owner: Youngjin · volatility: 中_

**L0 TL;DR**: 業務を1つ選び、既存の自動化・商用製品と比較します。限定実験で効果・総費用・運用可能性を確認して投資を拡大します。

## ① なぜ今なのか

公開モデルやシミュレーション・学習資産を評価できますが、製品公開・サービスGAは顧客業務の収益性を保証しません。[モデル選択](pillar-2.md)、[実行手順](execution.md)、[根拠](evidence.md)を結び、自社環境で試す仮説を作ります。

## ② 自社の産業にとって何を意味するか

| 業務例 | 先に測定するもの | 代替案 |
|---|---|---|
| 製造検査・部品取扱い | 不良・手戻り、時間、介入 | 既存ビジョン・制御改善、商用セル、SI |
| 物流搬送・積載 | 処理量、停止・復旧、環境変化 | 既存AMR・フリート製品、手順改善 |
| ロボット製品開発 | データ準備・学習・評価時間、実機失敗 | 開発環境改善、クラウド実験 |

ヒアリングの例です。特定モデルやヒューマノイドを全業務の既定解としません。

## ③ 何が本物で何が誇張なのか

| 判断 | 必要な条件 | 決定 |
|---|---|---|
| 限定実験 | 測定できる基準値、利用権、担当者、費用上限 | [パイロットカード](start.md#pilot)承認 |
| 現場パイロット | 独立評価で改善、遅延・安全・復旧試験計画 | 監督下で範囲限定 |
| 運用拡大 | 現場成果、実運用費、介入・復旧、支援責任 | 段階的に拡大 |
| 保留・代替 | 権利・安全責任未定、より経済的な代替、反復未達 | 条件解消または別方式 |

「GAだから今投資」「12～24か月で成果」という共通日程を使いません。製品公開・再現・現場検証を分けます。

## ④ では何から始めるか

[業務適合性8問](start.md#fit)を埋め、現行方式と比較します。学習が必要なら現在の課題に合わせデータ収集、シミュレーション、ファインチューニングを選びます。準備期間と学習実行時間を区別します。

**ROIは総費用で計算します。** ロボット・統合・データ・人員・安全検証の初期費用と、保守・介入・クラウドの運用費を含めます。[ROI用紙](start.md#roi)で低・基準・高の回収期間を確認します。

## ⑤ なぜAWSと進めるのか

既存AWSのデータ・セキュリティ・運用を再利用できるか確認し、小さく測定して必要なサービスだけ追加します。[意思決定](decisions.md)に単一GPU・管理型・複数ノードの選択条件があります。クラウド、モデル供給者、ロボット/SIの現場責任を別々に決めます。

ソウル対応だけで韓国内処理を保証しません（[AgentCore根拠](evidence.md#agentcore-residency)）。コードライセンスだけで重みの商用権を保証しません（[OpenVLA根拠](evidence.md#openvla-license)）。移行性を評価し「ロックインなし」を約束しません。

## 検討を始めるなら

業務責任者・技術チーム・AWS担当が[承認カード](start.md#pilot)を作ります。成果物は**業務1件、基準、費用・期限上限、運用・安全責任者、成功・中止条件**です。[実行手順](execution.md)と[配備ゲート](operations.md#release)へ接続します。
