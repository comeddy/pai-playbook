# 高管简报 — 业务价值与投资批准

_最后更新: 2026-09 · owner: Youngjin · volatility: 中_

**L0 TL;DR**: 选择一个业务任务，与现有自动化及商用产品比较。在有限实验中确认收益、总成本及可运营性，再扩大投资。

## ① 为什么是现在

可以评估公开模型及仿真/训练资产，但产品发布或服务 GA 不保证客户业务盈利。结合[模型选择](pillar-2.md)、[执行路径](execution.md)、[证据](evidence.md)，形成适用于自身环境的假设。

## ② 对我们的行业意味着什么

| 任务示例 | 先测量 | 替代方案 |
|---|---|---|
| 制造检测/零部件处理 | 缺陷、返工、周期、人工介入 | 现有视觉/控制改进、商用工作站、SI |
| 物流搬运/装载 | 吞吐量、停机恢复、环境变化 | 现有 AMR/机群产品、流程改进 |
| 机器人产品开发 | 数据准备/训练/评估时间、实机失败 | 现有开发环境改进、云实验 |

该表用于需求发现，不将特定模型或人形机器人设为所有业务的默认答案。

## ③ 什么是真实，什么是炒作

| 判断 | 所需条件 | 决定 |
|---|---|---|
| 有限实验 | 可测基线、使用权、负责人、费用上限 | 批准[试点卡](start.md#pilot) |
| 现场试点 | 独立评估改善、延迟/安全/恢复测试计划 | 有监督的有限范围 |
| 扩大运营 | 现场成果、实际运营费、介入恢复、支持责任 | 分阶段扩大 |
| 暂停/替代 | 权利或安全责任不明、替代方案更经济、重复未达标 | 补齐条件或选其他方式 |

不用“GA 所以现在投资”“12~24 个月后见效”的共同时间表。区分产品发布、实验复现、客户现场验证。

## ④ 从哪里开始

填写[八个业务问题](start.md#fit)，比较现有方式。需要学习时，按当前瓶颈选择数据采集、仿真或微调。区分准备时间和训练运行时间。

**按总成本计算 ROI**：初始机器人、集成、数据、人力、安全验证，以及持续维护、人工介入、云费用。使用 [ROI 表](start.md#roi)计算低/基准/高情景的回收期。

## ⑤ 为什么与 AWS 合作

评估现有 AWS 数据、安全和运营环境的复用，先小规模实测，再增加必要服务。[决策](decisions.md)涵盖单 GPU、管理型及多节点选择。分别约定云支持、模型供应商支持和机器人/SI 现场责任。

首尔可用不保证韩国境内处理（[AgentCore 证据](evidence.md#agentcore-residency)）。代码许可证不自动保证权重商用权（[OpenVLA 证据](evidence.md#openvla-license)）。评估可迁移性，不承诺“无锁定”。

## 开始评估

业务负责人、技术团队及 AWS 联系人共同填写[试点批准卡](start.md#pilot)：**一个任务、基线、费用/时间上限、运营/安全负责人、成功及停止条件**。然后进入[执行路径](execution.md)和[发布条件](operations.md#release)。
