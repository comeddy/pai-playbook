Why

Physical AI는 답이 흩어져 있는 도메인이다

Isaac Sim은 AWS에서 어떻게 돌리는지, VLA 파인튜닝 GPU는 어느 규모로 잡는지, sim-to-real gap은 정말 극복되는지 — 답은 슬랙 스레드, 벤더 블로그, 논문에 파편화되어 있다. 이 playbook은 그 파편을 검증 기준으로 걸러 한 곳에 계층화했다. 고객 미팅 5분 전에 열어도 방향이 잡히도록.

01

5분 안에 방향

급하면 FAQ Top 20으로 직행, 주제가 잡히면 5개 필러로, 갈림길에선 의사결정 트리로. 모든 항목은 L0(1~2문장) → L1(1페이지) → L2(deep-dive 링크)로 계층화되어 상단만 읽어도 방향이 잡힌다.

02

검증된 것만 담는다

성숙도 라벨(GA / Preview / Research-only / Hype)과 출처 등급 [1]~[4]로 모든 항목의 신뢰 수준을 명시. "인상적 데모"와 "배포 가능"을 구분한다. 포함 기준 미달 항목은 본문이 아닌 Radar 대기열에만 존재한다.

03

액션으로 끝난다

개념 설명으로 끝나는 항목은 미완성으로 간주한다. 모든 항목은 "➡️ SA 다음 액션"으로 마무리 — 읽고 나면 고객에게 무엇을 제안할지가 남는다.

What

5개 필러 + 3개 운영 페이지

필러 간 비중은 균등, 각 필러 내부는 고객 실제 수요 × production-readiness 순으로 정렬. 필러 상단엔 "고객이 가장 자주 묻는 질문 Top 3"가 있다.

P1

데이터 수집 & 처리

로봇 학습의 병목은 모델이 아니라 데이터다 — 텔레옵 · 오픈 데이터셋 · 합성 데이터를 AWS 파이프라인으로 처리하는 법.

P2

모델 학습 (VLA)

VLA/로봇 파운데이션 모델을 어느 규모의 GPU로, 파인튜닝인지 사전학습인지부터 갈라서 설계하는 법.

P3

시뮬레이션

Isaac Sim/Lab vs 오픈소스 선택과 AWS 위에서의 대규모 병렬 시뮬레이션 실행 패턴.

P4

Sim-to-Real

시뮬레이션에서 학습한 정책을 실기체로 옮기는 검증된 방법론과 엣지 추론 배포 경로.

P5

에이전트 오케스트레이션

LLM 플래너(System 2)가 로봇 컨트롤러(System 1)와 플릿을 지휘하는 계층 — Bedrock AgentCore 중심.

Decisions

의사결정 트리 ×4

고객이 자주 부딪히는 4개 갈림길을 산문 대신 결정 표/트리로. 급하면 해당 표만 보고 방향을 잡는다.

Radar

대기열 / 관찰 목록

"이거 왜 없어요?"의 답. 포함 기준 미달로 대기 중인 항목이 한 줄로 존재하고, 기준 충족 시 본문으로 승격된다.

Maintenance

유지보수 규칙

소유권 · 갱신 규칙 · 승격 파이프라인. 새 후보 제보는 이 파이프라인을 통해 본문에 반영된다.

Decide

4개 갈림길, 표 하나로 판정

각 결정은 필러를 가로지른다. 트리와 비교표, 그리고 한 줄 판정 원칙까지.

Physical AI Playbook의 4개 교차 의사결정 트리와 각 핵심 질문, 판정 원칙
갈림길핵심 질문판정 원칙
Cloud vs Edge "이 추론을 클라우드에 둘 수 있나, 엣지에 둬야 하나?" 가장 중요한 판별자는 제어 주파수. 실시간 안전·반응 루프면 엣지, 생각할 시간이 있으면 클라우드 — action chunking이 다리.
NVIDIA vs 오픈소스 "Isaac에 다 걸까, 오픈소스로 갈까?" 워크로드로 고르면 된다. "AWS는 셋 다 잘 돌린다" — Isaac Sim/Lab · MuJoCo/MJX · Gazebo 모두 중립 포지션.
GPU 확보 전략 "On-Demand가 안 잡힌다. 뭘 써야 하나?" 시작은 On-Demand. 못 잡히거나 대규모면 Capacity Blocks / Flexible Training Plans로.
Build vs Buy "파운데이션 모델을 파인튜닝할까, 자체 학습할까?" 거의 항상 파인튜닝(Buy+adapt)이 답. 밑바닥 사전학습은 극소수 — 상용은 라이선스가 첫 게이트.

※ 인스턴스 · 리전 세부는 휘발성 — 판정 전 playbook의 최신 리전 표를 확인한다.

성숙도 라벨 — 4단계

🟢 GA — 프로덕션 사용 가능 🟡 Preview 🔵 Research-only — 제안 금지 ⚪ Hype — 데모만 존재

"인상적 데모" ≠ "배포 가능". 라벨이 그 경계를 지킨다.
