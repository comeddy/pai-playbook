What

5 大支柱 + 3 个运营页面

各支柱权重均等；支柱内部按客户真实需求 × production-readiness 排序。每个支柱顶部列有“客户最常问的 Top 3 问题”。

P1

数据采集与处理

机器人学习的瓶颈不是模型而是数据 — 如何用 AWS 流水线处理遥操作、开放数据集与合成数据。

P2

模型训练 (VLA)

VLA/机器人基础模型该用多大规模的 GPU，先分清微调还是预训练，再做设计。

P3

仿真

Isaac Sim/Lab 与开源方案的选择，以及在 AWS 上的大规模并行仿真执行模式。

P4

Sim-to-Real

把仿真中学到的策略迁移到实体机的成熟方法论，以及边缘推理部署路径。

P5

智能体编排

LLM 规划器（System 2）指挥机器人控制器（System 1）与机群的层级 — 以 Bedrock AgentCore 为核心。

Physical AI Playbook 的 4 个交叉决策树及其核心问题与判定原则
岔路口核心问题判定原则
Cloud vs Edge “这个推理能放云端，还是必须放边缘？” 最关键的判别因素是控制频率。实时安全/反应回路放边缘，有思考余地就放云端 — action chunking 是桥梁。
NVIDIA vs 开源 “全押 Isaac，还是走开源？” 按工作负载选即可。“AWS 三者都跑得好” — Isaac Sim/Lab · MuJoCo/MJX · Gazebo 均为中立立场。
GPU 获取策略 “On-Demand 抢不到，该用什么？” 先用 On-Demand。抢不到或规模大时转向 Capacity Blocks / Flexible Training Plans。
Build vs Buy “微调基础模型，还是自研训练？” 几乎总是微调（Buy+adapt）。从零预训练只属于极少数 — 商用时许可证是第一道门槛。
