# メンテナンス — 掲載・根拠・更新ルール

_最終更新: 2026-09 · owner: Youngjin · volatility: 中_

**L0 TL;DR**: 関連性・発売状態・根拠・用途・支援主体を分けます。自動化は欠落・不一致を確認し、事実確認と現場承認は人が担当します。

## 掲載基準 (THE FILTER)

以前の「4つのうち2つ」は**関連性の参考信号**に限定します。顧客需要、AWSとの対応、発売状態、現場事例が対象で、対応付けとロードマップだけでは検証を通過しません。

掲載には**全て**必要です：(1) 顧客課題またはR&Dの問い、(2) 正確な一次資料・日付・版、(3) 根拠・限界・許可用途、(4) ownerと実行可能な次の行動。数値には条件・標本・単位を付け、原文未確認はRadarに残します。

研究は仮説検証のR&D案内に使用できますが運用性能の保証には使いません。運用拡大には[カード](start.md#pilot)と[現場ゲート](operations.md#release)の根拠が必要です。

## 成熟度・出典・用途

| 次元 | 表示 | 解釈 |
|---|---|---|
| 発売 | GA / Preview / Research / 対象外 | 製品別。原理・規制・アルゴリズムにGAを付けません |
| 根拠 | メーカー発表 / 原文照合 / 再現実験 / 顧客現場検証 | 自動的に次段階と見なしません |
| 用途 | 学習・R&D / PoC検討 / 運用拡大検討 | 検証範囲と限界を記録 |
| 支援 | AWSサービス / モデル供給者 / パートナーSI / サンプル作者 | 契約と現場責任を分離 |

`[1]`公式資料・論文、`[2]`記録のある再現、`[3]`メーカー発表、`[4]`未確認は**出典種別**です。順位やAWS公式承認ではありません。`[2]`には実行者・版・環境・ログ・条件が必要で、旧記録にログがなければ再現根拠として引用しません。発表はGA、1回実行は本番検証を意味しません。

## メタデータと鮮度

ページに`_owner: 名前 · updated: YYYY-MM · volatility: 高/中/低_`を保持します。日付は**ページ編集・確認範囲**であり、部分修正で別主張の日付を更新しません。ページバッジは高1・中3・低6か月超過を通知します。

判断に影響する主張を[根拠記録](evidence.md)へ追加します。`checked_on`は原文照合日、`review_after_days`は主張別周期、`pages`は影響する要約・ピラーです。未移行の既存主張は記録外と明示します。


L0を短くし詳細はリンク・折り畳みにします。難語の初出に`[^term]`、末尾`<!-- 용어 각주 -->`下に1～2文の定義を付けます。翻訳はID・URL・構造を保持します。経営層要約でも条件・限界を省きません。公開文書に顧客機密・営業戦略を記載しません。

## Playbook 昇格パイプライン

1. Radar・候補フォームに主題・出典・顧客課題を記載します。
2. ownerが掲載条件と専門確認担当を定めます。自動走査だけでは昇格しません。
3. 根拠・版・日付・条件を照合し、R&D・PoC・現場検証の範囲を明示します。
4. 韓国語原文・影響要約・en/zh/jaを同時更新します。
5. 根拠表示生成、ハッシュ同期、検査、レビューの順で反映します。

## 検査と限界

```bash
python3 scripts/check_evidence.py
python3 scripts/check_translation_sync.py
python3 scripts/check_nav_index_sync.py
python3 scripts/check_staleness.py --check
mkdocs build --strict
```

根拠構造・表示不一致、nav不一致、メタ欠落、内部リンク・アンカーエラーは配備を止めます。期限超過・人の確認待ちは報告し、翻訳ずれは現在CIで警告のみです。コミット前に別途**翻訳ずれゼロ**を確認します。ビルドは外部URL到達性、事実、翻訳の意味、ロボット実行を検証しません。
