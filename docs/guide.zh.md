# 指南 — 使用方法与验证范围

_最后更新: 2026-09 · owner: Youngjin · volatility: 中_

**L0 TL;DR**: 客户在[开始指南](start.md)判断业务、ROI、试点；工程团队使用[执行路径](execution.md)及[运营恢复](operations.md)。AWS 员工使用[对话指南](exec-guide.md)。

## 阅读顺序

业务判断 → 架构决策 → 对应支柱 → 实验评估 → 运营交接。新主题见 [Radar](radar.md)，来源及日期见[证据](evidence.md)。

## 验证流程

候选收集 → 一手来源对照 → 问题/证据/用途/owner 复核 → 原文翻译更新 → 结构检查 → 审查。扫描仅收集候选，不批准晋升。旧“4 项中 2 项”仅为相关性信号（[维护](maintenance.md)）。

## 自动检查范围

| 检查 | 范围 | 不保证 |
|---|---|---|
| 页面时效 | 页面元数据日期 | 所有主张已重查 |
| 主张证据 | 日期、必填项、影响页、多语言显示 | 来源真实及现场适用 |
| 翻译哈希 | 翻译对应的原文版本 | 语义准确 |
| Strict 构建 | 内部文档链接、锚点、配置 | 外链可达、技术主张及执行成功 |

复核应查看逐项日期、复现日志、人工状态，而非只看页面徽章。[维护](maintenance.md)说明流程，[claims.json](assets/claims.json)保存机器可读记录。
