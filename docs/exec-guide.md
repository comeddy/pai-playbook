# 고객 대화 가이드 — AWS 직원용

_최종 갱신: 2026-09 · owner: Youngjin · volatility: 중간_

**L0 TL;DR**: 고객의 업무·비용·운영 조건을 확인하고 기술 선택을 돕는다. 공개 문서이며 내부 고객 정보·영업 기록은 포함하지 않는다. 고객에게 보여줄 요약은 [경영진 브리핑](exec.md), 함께 채울 양식은 [시작 가이드](start.md)다.

## 1. 미팅 흐름

1. **업무**: 어떤 반복 작업의 시간·실패·개입을 줄이려는지 확인한다.
2. **대안**: 기존 자동화, 상용 제품, 로봇 SI, 모델 적응을 비교한다.
3. **실험**: 데이터 권리·인력·한도를 확인하고 병목 하나의 실험을 정한다.
4. **종료 조건**: 성공·중단·인계 기준과 다음 회의에서 검토할 증거를 합의한다.

## 2. 주요 질문과 답변

| 질문 | 답변에 포함할 내용 | 도구 |
|---|---|---|
| ROI는? | GPU 외 로봇·SI·데이터·인력·안전·운영을 포함한 총비용과 실현 가능한 효과 | [ROI](start.md#roi) |
| 왜 AWS인가? | 기존 환경 재사용, 실측한 병목, 필요한 서비스와 지원 경계 | [의사결정](decisions.md) |
| 인력은? | 로봇·ML·클라우드·현장 안전 역할. 부족한 역량은 파트너/SI 범위로 명시 | [책임자](operations.md#layers) |
| 언제 성과가 나오나? | 준비 상태와 평가 계획을 바탕으로 기간 범위 제시. 1일 PoC/12~24개월 공통 약속 금지 | [실행](execution.md) |
| 안전은? | 툴 권한과 독립적인 물리 안전, 로컬 제어, 취소·복구 시험, 현장 승인 책임 | [운영](operations.md) |
| 한국 안에서 처리되나? | 저장·모델 추론·Memory/Evaluations·외부 툴 경로 각각 확인 | [근거](evidence.md#agentcore-residency) |
| 오픈 모델이면 상용 가능한가? | 코드·가중치·기반 모델·데이터의 버전별 조건 확인 | [P2](pillar-2.md) |
| 파트너는 어떻게 고르나? | 유사 태스크 현장 실적, 로봇 지원, 통합·안전 책임, 복구·유지보수 범위 | [파일럿 카드](start.md#pilot) |

## 3. 인계와 지원 경계

AWS 담당자는 서비스 아키텍처·할당량·요금·서비스 지원 범위를 확인한다. 로봇/ML 팀은 데이터·모델·장치 호환성과 평가를 담당한다. SI/현장 담당은 공정 통합·안전·운영 복구를 책임진다. 샘플 유지보수자에게 고객 운영 SLA가 있다고 가정하지 않는다. 담당자와 미해결 항목을 카드에 기록한다.

| “Cedar가 로봇 안전을 보장합니다” | “툴 권한 외에 독립 안전·로컬 제어·현장 검증이 필요합니다” |
