# 顧客対話ガイド — AWS担当者向け

_最終更新: 2026-09 · owner: Youngjin · volatility: 中_

**L0 TL;DR**: 顧客の業務・費用・運用条件を確認し、技術選択を支援します。公開文書であり、顧客機密や営業記録を含みません。提示用は[経営層ブリーフィング](exec.md)、共同記入用は[開始ガイド](start.md)です。

## 1. 面談の流れ

1. **業務**：時間・失敗・介入を減らす反復作業を確認します。
2. **代替案**：既存自動化、製品、ロボットSI、モデル適応を比較します。
3. **実験**：利用権・人員・上限を確認し、課題1つを試験します。
4. **終了条件**：成功・中止・引継ぎと次回確認する証拠を合意します。

## 2. 主な質問

| 質問 | 回答に含める内容 | ツール |
|---|---|---|
| ROIは？ | GPU以外のロボット・SI・データ・人員・安全・運用総費用と実現可能効果 | [ROI](start.md#roi) |
| なぜAWS？ | 既存環境再利用、実測課題、必要サービスと支援境界 | [意思決定](decisions.md) |
| 人員は？ | ロボット・ML・クラウド・安全の役割、不足部分のSI/パートナー範囲 | [担当者](operations.md#layers) |
| 成果はいつ？ | 準備・評価計画による範囲。共通の1日・12～24か月を保証しません | [実行](execution.md) |
| 安全は？ | ツール権限に加え独立安全、ローカル制御、取消復旧試験、現場承認 | [運用](operations.md) |
| 韓国内処理？ | 保存、推論、Memory/Evaluations、外部ツール経路を個別確認 | [根拠](evidence.md#agentcore-residency) |
| オープンモデルは商用可能？ | コード・重み・基盤モデル・データの版別条件 | [P2](pillar-2.md) |
| パートナー選定？ | 類似現場実績、機体支援、統合・安全責任、復旧・保守範囲 | [カード](start.md#pilot) |

## 3. 引継ぎと支援境界

AWS担当はサービス構成・クォータ・料金・支援範囲を確認します。ロボット/MLチームはデータ、モデル・機体互換性、評価を担当します。SI/現場は工程統合・安全・復旧を担当します。サンプル作者に顧客運用SLAがあると仮定せず、担当と未解決事項を記録します。

## 4. 避ける約束

| 避ける表現 | 代替表現 |
|---|---|
| 「ソウルGAなのでレジデンシ問題なし」 | 「機能・モデル別に保存・処理場所を確認します」 |
| 「OpenVLAはMITなので商用可能」 | 「コードと重みの条件を分けて確認します」 |
| 「100実演で1日80%」 | 「固定評価条件で必要データ・時間を測ります」 |
| 「Cedarがロボット安全を保証」 | 「独立安全・ローカル制御・現場検証も必要です」 |
| 「オープンならロックインなし」 | 「モデル・データ・運用ツールの移行費用を比較します」 |

**➡️ 次のアクション**：推進・保留・代替案、費用・期限上限、担当者、次段階の証拠を1枚にして共有します。
