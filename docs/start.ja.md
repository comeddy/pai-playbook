# はじめに — 業務適合性・ROI・パイロット承認

_最終更新: 2026-11 · owner: Youngjin · volatility: 中_

**L0 TL;DR**: 技術より先に業務を見ます。まず、どの業務を改善したいのか、今どれくらいできているのかを書き出しましょう。次に、既存の自動化・商用製品・SI[^si]で解決できないかを確かめます。それでもロボットが新しく学ぶ必要が残る場合にだけ、データ・シミュレーション・VLAを検討します。このページは顧客とAWS担当者が一緒に埋めていく判断シートです。

## 役割別の経路 { #roles }

| 役割 | 最初に読むもの | 会議の成果物 |
|---|---|---|
| 顧客の意思決定者 | 本ページ → [経営層ブリーフィング](exec.md) | 業務1件、予算上限、推進・保留条件 |
| 顧客の技術チーム | [実行手順](execution.md) → 該当ピラー → [運用と復旧](operations.md) | 前提条件、実験計画、担当者 |
| AWS担当者 | [対話ガイド](exec-guide.md) → [意思決定](decisions.md) | ヒアリング、代替案、支援・パートナーの分担 |

担当者向けガイドも公開文書です。社内連絡先や顧客の機密資料を本サイトに記録しないでください。

## 業務適合性 — 初回面談の8問 { #fit }

| 質問 | 顧客と記入する内容 |
|---|---|
| 改善する業務は何ですか？ | 工程、物体、環境、開始・完了条件を1文で記載 |
| 現状の実績は？ | 時間当たり完了数、サイクル時間、失敗・手戻り率、人の介入回数 |
| 既存方式では何が不足しますか？ | ルール型自動化、制御改善、製品、SI見積を比較 |
| 学習が必要な変化は？ | 物体、照明、配置、指示の変化と実際の頻度 |
| 保有する資源は？ | ロボット、センサー、ログ、実演、CAD、利用権、人員 |
| 現場の制約は？ | 人の接近、通信断、遅延、電力、データ処理国 |
| 運用・復旧担当者は？ | 現場、ロボット/SI、ML、クラウドの実名担当者 |
| 中止する条件は？ | 費用・期間上限、基準方式に対する最低改善、安全・復旧条件 |

**推進**：業務と基準値が測定でき、改善仮説、実験資源、運用責任者がいます。**保留**：利用権、現場責任、費用上限のいずれかが未定です。**代替案**：商用製品や既存の自動化が低い総費用で要件を満たします。[Build vs Buy](decisions.md#4-build-vs-buy基盤モデル)に選択を記録します。

## 総費用とROI — GPU見積だけで判断しません { #roi }

**低・基準・高の3シナリオ**で算出します。未確認の費用はゼロではなく「見積待ち」とします。下の計算機に数量・単価・期間を直接入力すると結果がすぐに計算され、入力値と結果をCSVでダウンロードしてプロジェクト文書に添付できます（USDの記入用紙で、価格表ではありません）。

| 費用区分 | 含める項目 |
|---|---|
| 初期固定費 | ロボット、グリッパー、センサー、設置・SI、データ収集・整備、環境制作、安全審査・検証 |
| 実験変動費 | GPUインスタンス時間、保存・転送・ログ、モデル/API、失敗・再実行、実験人員 |
| 継続運用費 | 保守、部品、監視、人の介入、推論・接続、再学習・現場再検証 |
| 期待効果 | 実際に減少する手戻り・停止、実現可能な処理量増加の価値、再配置できる人員時間 |

| 指標 | 計算方法 | 読み方 |
|---|---|---|
| **初期投資** | 初期固定費 + 実験変動費 | パイロット開始から検証完了までに一度だけかかる費用 |
| **期間運用費** | 月間継続運用費 × 期間（か月） | 分析期間中に継続して発生する費用 |
| **期間効果** | 月間期待効果 × 期間（か月） | 分析期間中に実際に得られる価値 |
| **期間純便益** | 期間効果 − 期間運用費 | 運用して残る金額 — 初期投資は差し引く前の値 |
| **回収期間** | 初期投資 ÷ 月間純便益 | 初期投資を取り戻すまでの月数。月間純便益（月間効果 − 月間運用費）がゼロ以下なら「回収不可」 |
| **期間ROI** | (期間効果 − 初期投資 − 期間運用費) ÷ (初期投資 + 期間運用費) | 支出全体に対する残りの割合。0%未満なら分析期間内では損失 |

シミュレーションは実験費を減らせますが、環境制作・校正・実機検証を不要にはしません。同一の効果について生産性向上と人件費削減を二重計上しません。見積と効果の仮定に出典・確認日を記録します。

## パイロット承認カード { #pilot }

パイロットを始める前に、顧客と一緒に以下の 10 の問いに答えます。**空欄が残っていれば、まだ始める時期ではありません。** 例は理解のための仮の値です。期間、実演数、成功率は顧客ごとの合意事項であり、共通の保証値ではありません。

| # | 項目 | ひとことで言うと | 例（仮の値） |
|---|---|---|---|
| 1 | 業務 / 対象外 | ロボットに正確に何をさせるか？ 今回やら**ない**ことは？ | 混載箱から部品をつかみトレイに置く。破損品の処理・夜間勤務は対象外 |
| 2 | 現在の方式 / 代替案 / 基準値の測定期間 | 今はどのように、どの程度うまくやっているか？ ロボット以外の解決策（既存の自動化・市販製品）とも比べるか？ 現在の実力を何日測って比較の基準にするか？ | 作業者 2 名で毎時 300 個、誤り 2%。市販ピッキングセルの見積もりと比較。2 週間測定 |
| 3 | 目標指標 / 最低改善 / 測定条件 | 何で成功を判断するか？ 最低どれだけ良くなれば意味があるか？ どの条件で測るか？ | 成功率・毎時処理量。基準値より処理量 20% 以上改善。実際のライン速度・照明で測定 |
| 4 | 評価標本数 / 反復実行 / 未学習環境 | 何回試すか？ もう一度やっても結果は近いか？ 学習時に見ていない物・配置でも動くか？ | 試行 200 回、3 日に分けて反復、学習にない部品 5 種を含む |
| 5 | データ・コード・重みの利用権 | 収集したデータ、使ったコード、学習済みモデルファイル（重み）は誰のものか、商用利用できるか？ | データは顧客所有。使うオープンモデルのライセンスが商用利用を認めるか確認 |
| 6 | 担当者 | 分野ごとに責任者を 1 名ずつ決めたか？ | 現場運用・ロボット/SI・ML・クラウド・安全の担当を各 1 名 |
| 7 | 費用 | 最初にかかる費用、実験期間の費用、運用時の毎月の費用は？ 楽観・基準・悲観の 3 つの値で | 初期 / 実験 / 月運用をそれぞれ低・基準・高で記録 |
| 8 | 上限 | いくらまで、いつまで使うか？ 延ばすには誰の承認が必要か？ | 支出上限、終了日、延長は事業部長が承認 |
| 9 | 中止条件 | どんな場合に止めるか？ 始める前に決めておく | 終了日までに最低改善に届かない・支出上限超過・非常停止/復旧試験の失敗のいずれか |
| 10 | 次段階の証拠 / 承認者 | 次の段階へ進むには何を示し、誰が承認するか？ | 評価レポート・費用実績・安全点検表 → 工場長が承認 |

以下のブロックをプロジェクト文書にコピーして記入します。

```text
1. 業務: ロボットがやること / 今回対象外のこと:
2. 基準値: 現在の方式と成果 / 比較する代替案 / 測定期間:
3. 目標: 成功指標 / 最低改善幅 / 測定条件:
4. 評価: 試行回数 / 反復回数 / 学習にない環境:
5. 権利: データ・コード・モデル（重み）の所有と利用範囲:
6. 担当者: 現場 / ロボット-SI / ML / クラウド / 安全:
7. 費用（低・基準・高）: 初期 / 実験 / 月運用:
8. 上限: 最大支出 / 終了日 / 延長承認者:
9. 中止条件: 目標未達 / 予算超過 / 安全・復旧試験失敗:
10. 次段階: 示す証拠 / 承認者:
```

**段階別条件**：基準値の確保 → [隔離実験](execution.md) → [限定的な現場検証](operations.md) → 運用拡大。毎回、指標、費用、介入、復旧結果を確認します。技術のGAや共通の「12～24か月」予測で次段階を承認しません。

**➡️ 次のアクション**：次回面談でカードを1枚埋め、推進・保留・代替案を決めます。推進する場合は現在のボトルネックに対応する[実行手順](execution.md)を1つ選びます。

<!-- 용어 각주 -->
[^si]: **SI（System Integrator）** — 顧客の現場に合わせてロボット・設備・制御・ソフトウェアを統合する事業者です。クラウドのサービス支援とセルの統合・安全の責任は別途定めます。
