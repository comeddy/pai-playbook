# 가이드 — 사용법과 검증 범위

_최종 갱신: 2026-09 · owner: Youngjin · volatility: 중간_

**L0 TL;DR**: 고객은 [시작 가이드](start.md)에서 업무·ROI·파일럿을 결정하고, 기술팀은 [실행 경로](execution.md)와 [운영·복구](operations.md)를 사용한다. AWS 직원의 대화 준비는 [직원용 가이드](exec-guide.md)에 있다.

## 자료를 읽는 순서

업무 판단 → 의사결정 → 해당 필러 → 실험·평가 → 운영 인계 순으로 읽는다. 새 기술 탐색은 [Radar](radar.md), 출처·검토일 확인은 [근거 기록](evidence.md)을 사용한다.

## 검증 파이프라인

후보 수집 → 1차 출처 대조 → 고객 문제·근거·사용 범위·소유자 확인 → 원문·번역 갱신 → 구조 검사 → 리뷰. 자동 스캔은 후보를 모으며 승격을 승인하지 않는다. 기존 ‘4개 중 2개’는 관련성 신호일 뿐이다([유지보수 규칙](maintenance.md)).

## 자동 검사가 확인하는 것

| 검사 | 확인 범위 | 보장하지 않는 것 |
|---|---|---|
| 페이지 신선도 | 페이지 메타 날짜의 경과 | 모든 주장이 다시 검증됨 |
| 주장별 근거 | 날짜·필수 필드·영향 페이지·언어별 표시 | 원문 사실·현장 적합성 |
| 번역 해시 | 어떤 원문에 맞춰 갱신했는지 | 번역 의미의 정확성 |
| strict 빌드 | 문서 내부 링크·앵커·구성 오류 | 외부 링크 접속·기술 주장·실행 성공 |

검토 담당자는 페이지 배지만 보지 말고 주장별 확인일·재현 로그·사람 검토 상태를 확인한다. 운영·검증 절차는 [유지보수](maintenance.md), 기계가 읽는 근거는 [claims.json](assets/claims.json)에 있다.
