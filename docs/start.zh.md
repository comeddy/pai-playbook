# 开始 — 业务适配、ROI 与试点批准

_最后更新: 2026-11 · owner: Youngjin · volatility: 中_

**L0 TL;DR**: 先看业务，再看技术。先写下想改善哪项业务、现在做得怎么样。接着看看现有自动化、商用产品或系统集成商（SI）[^si]能否解决。只有仍有需要机器人新学的部分时，再考虑数据、仿真或 VLA。本页是客户与 AWS 员工一起填写的判断表。

## 按角色选择路径 { #roles }

| 角色 | 先阅读 | 会议产出 |
|---|---|---|
| 客户决策者 | 本页 → [高管简报](exec.md) | 一个任务、费用上限、推进/暂停标准 |
| 客户技术团队 | [执行路径](execution.md) → 对应支柱 → [运营与恢复](operations.md) | 前置条件、实验计划、负责人 |
| AWS 员工 | [对话指南](exec-guide.md) → [决策](decisions.md) | 需求问题、替代方案、支持及合作伙伴分工 |

员工指南同样公开。不要在本站记录内部联系方式或客户机密材料。

## 业务适配 — 首次会议的八个问题 { #fit }

| 问题 | 与客户填写 |
|---|---|
| 要改善什么任务？ | 用一句话描述工序、物体、环境、开始及完成条件 |
| 目前表现如何？ | 每小时完成量、周期、失败/返工率、人工介入次数 |
| 现有方式为何不足？ | 比较规则自动化、控制改进、商用产品和 SI 报价 |
| 哪些变化需要学习？ | 物体、光照、布局、指令变化及实际频率 |
| 已有哪些资源？ | 机器人、传感器、日志、演示、CAD、使用权、人员 |
| 现场限制是什么？ | 人员接近、断网、延迟、功率、数据处理国家 |
| 谁负责运行和恢复？ | 现场、机器人/SI、ML、云的实名负责人 |
| 什么情况下停止？ | 费用/时间上限、相对基线的最小改善、安全及恢复条件 |

**推进**：任务和基线可测量，有改善假设、实验资源及运营负责人。**暂停**：使用权、现场责任或费用上限未明确。**选择替代方案**：商用产品或现有自动化以更低总成本满足需求。在 [Build vs Buy](decisions.md#4-build-vs-buy基础模型) 中记录选择。

## 总成本与 ROI — 不只看 GPU 报价 { #roi }

分别计算**低/基准/高情景**。未知费用写“待报价”，不要填零。在下方计算器中直接输入数量、单价及周期，结果即时计算，并可将输入值与结果下载为 CSV 附到项目文档中（USD 表单，并非价目表）。

| 费用类别 | 包含项目 |
|---|---|
| 初始固定费用 | 机器人、夹爪、传感器、安装/SI、数据采集清洗、环境制作、安全审查验证 |
| 实验变动费用 | GPU 实例小时、存储/传输/日志、模型/API、失败重试、工程人员 |
| 运营经常费用 | 维护、零部件、监控、人工介入、推理连接、再训练及现场复核 |
| 预期收益 | 实际减少的返工及停机、可兑现的吞吐量价值、可重新安排的人力时间 |

| 指标 | 计算方法 | 如何解读 |
|---|---|---|
| **初始投资** | 初始固定费用 + 实验变动费用 | 从试点开始到完成验证的一次性支出 |
| **期间运营费用** | 月运营经常费用 × 期间（月） | 分析期间内持续发生的支出 |
| **期间收益** | 月预期收益 × 期间（月） | 分析期间内实际获得的价值 |
| **期间净收益** | 期间收益 − 期间运营费用 | 运营后剩余的金额——尚未扣除初始投资 |
| **回收期** | 初始投资 ÷ 月净收益 | 收回初始投资所需的月数。月净收益（月收益 − 月运营费用）为零或负时为“无法回收” |
| **期间 ROI** | (期间收益 − 初始投资 − 期间运营费用) ÷ (初始投资 + 期间运营费用) | 相对全部支出的回报率。低于 0% 表示分析期间内亏损 |

仿真可降低实验费用，但不消除环境制作、校准及实机验证费用。不要重复计算同一收益的生产率提升与人工节省。记录估价和收益假设的来源及确认日期。

## 试点批准卡 { #pilot }

试点开始前，与客户一起回答以下 10 个问题。**只要还有空栏，就说明还不到开始的时候。** 示例是帮助理解的假设值。周期、演示数量、成功率由客户场景约定，不是通用承诺。

| # | 项目 | 通俗地说 | 示例（假设值） |
|---|---|---|---|
| 1 | 任务 / 排除范围 | 到底让机器人做什么？这次**不**做哪些事？ | 从混装箱中抓取零件放到托盘上。破损件处理、夜班不在范围内 |
| 2 | 现有方式 / 替代方案 / 基线测量期间 | 现在怎么做、做得怎么样？是否也与非机器人方案（现有自动化、商用产品）比较？用几天测量当前水平作为比较基线？ | 2 名作业员每小时 300 件，错误率 2%。与商用拣选单元报价比较。测量 2 周 |
| 3 | 目标指标 / 最小改善 / 测量条件 | 用什么判断成功？至少改善多少才有意义？在什么条件下测量？ | 成功率与每小时处理量。处理量比基线提高至少 20%。在实际产线速度与照明下测量 |
| 4 | 评估样本数 / 重复运行 / 未学习环境 | 试多少次？重复做结果是否接近？在训练中没见过的物品和摆放下能否工作？ | 尝试 200 次，分 3 天重复，包含训练中没有的 5 种零件 |
| 5 | 数据、代码、权重使用权 | 采集的数据、使用的代码、训练出的模型文件（权重）归谁所有，能否商用？ | 数据归客户所有。确认所用开放模型的许可证是否允许商用 |
| 6 | 负责人 | 每个领域是否各定了 1 名负责人？ | 现场运营、机器人/SI、ML、云、安全各 1 名 |
| 7 | 费用 | 初始费用、实验期费用、运营后每月费用各是多少？按乐观、基准、悲观 3 个值填写 | 初始 / 实验 / 月运营分别记录低、基准、高 |
| 8 | 上限 | 最多花多少、到什么时候？延长需要谁批准？ | 支出上限、截止日，延长由事业部负责人批准 |
| 9 | 停止条件 | 什么情况下停止？开始前事先定好 | 截止日前未达最小改善、超出支出上限、急停/恢复测试失败，满足任一即停止 |
| 10 | 下一阶段证据 / 批准人 | 进入下一阶段需要展示什么，由谁批准？ | 评估报告、费用实绩、安全检查表 → 厂长批准 |

将下面的区块复制到项目文档中填写。

```text
1. 任务: 机器人要做的事 / 本次排除的事:
2. 基线: 现有方式与成绩 / 比较的替代方案 / 测量期间:
3. 目标: 成功指标 / 最小改善幅度 / 测量条件:
4. 评估: 试验次数 / 重复次数 / 训练中没有的环境:
5. 权利: 数据、代码、模型（权重）的归属与使用范围:
6. 负责人: 现场 / 机器人-SI / ML / 云 / 安全:
7. 费用（低-基准-高）: 初始 / 实验 / 月运营:
8. 上限: 最大支出 / 截止日 / 延长批准人:
9. 停止条件: 未达标 / 超预算 / 安全恢复测试失败:
10. 下一阶段: 要展示的证据 / 批准人:
```

**阶段条件**：建立基线 → [隔离实验](execution.md) → [有限现场验证](operations.md) → 扩大运营。每阶段审查指标、费用、人工介入及恢复结果。技术 GA 或通用“12~24 个月”预测不构成进入下一阶段的批准。

**➡️ 后续行动**：下次客户会议填写一张卡，决定推进、暂停或替代方案。推进时只选择适合当前瓶颈的一条[执行路径](execution.md)。

<!-- 용어 각주 -->
[^si]: **SI（System Integrator，系统集成商）** — 在客户现场集成机器人、设备、控制和软件的服务商。云服务支持与工作站集成、安全责任应分别指定。
