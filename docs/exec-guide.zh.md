# 客户对话指南 — AWS 员工用

_最后更新: 2026-09 · owner: Youngjin · volatility: 中_

**L0 TL;DR**: 先确认客户业务、费用、运营条件，再协助技术选择。本公开指南不包含客户机密或销售记录。客户摘要见[高管简报](exec.md)，共同填写[开始指南](start.md)。

## 1. 会议流程

1. **业务**：确认要减少时间、失败、介入的重复任务。
2. **替代**：比较既有自动化、产品、机器人 SI、模型适配。
3. **实验**：确认使用权、人力、上限，实验一个瓶颈。
4. **退出条件**：约定成功、停止、交接和下次审查的证据。

## 2. 主要问题

| 问题 | 回答内容 | 工具 |
|---|---|---|
| ROI？ | GPU 以外的机器人/SI/数据/人力/安全/运营总成本及可兑现收益 | [ROI](start.md#roi) |
| 为什么 AWS？ | 现有环境复用、实测瓶颈、必要服务及支持边界 | [决策](decisions.md) |
| 人员？ | 机器人、ML、云、现场安全角色；缺失能力的伙伴/SI 范围 | [负责人](operations.md#layers) |
| 何时见效？ | 按准备及评估计划给范围，不承诺通用一天或 12~24 个月 | [执行](execution.md) |
| 安全？ | 工具权限之外的独立物理安全、本地控制、取消恢复测试、现场批准 | [运营](operations.md) |
| 韩国境内处理？ | 分别检查存储、推理、Memory/Evaluations、外部工具路径 | [证据](evidence.md#agentcore-residency) |
| 开放模型可商用？ | 按版本检查代码、权重、基础模型及数据条款 | [P2](pillar-2.md) |
| 如何选伙伴？ | 类似任务现场实绩、机器人支持、集成安全责任、恢复维护范围 | [试点卡](start.md#pilot) |

## 3. 交接与支持

AWS 员工确认服务架构、配额、价格及服务支持范围。机器人/ML 团队负责数据、模型设备兼容和评估。SI/现场团队负责工艺集成、安全、运营恢复。不要假定样本维护者提供客户运营 SLA。记录负责人及未解决事项。

## 4. 避免的承诺

| 避免 | 替代表达 |
|---|---|
| “首尔 GA 所以数据驻留无问题” | “按功能及模型确认存储和处理位置” |
| “OpenVLA 是 MIT 所以可商用” | “分别核对代码与权重条件” |
| “100 演示一天达 80%” | “在固定评估条件下测量数据和时间需求” |
| “Cedar 保证机器人安全” | “还需独立安全、本地控制及现场验证” |
| “开放模型没有锁定” | “比较模型、数据及运营工具的迁移成本” |

**➡️ 后续行动**：用一页共享推进/暂停/替代决定、费用时间上限、负责人及下一阶段证据。
