# ガイド — 使い方と検証範囲

_最終更新: 2026-09 · owner: Youngjin · volatility: 中_

**L0 TL;DR**: 顧客は[開始ガイド](start.md)で業務・ROI・パイロットを判断し、技術チームは[実行手順](execution.md)と[運用復旧](operations.md)を使います。AWS担当は[対話ガイド](exec-guide.md)で準備します。

## 読む順序

業務判断 → 構成判断 → 対象ピラー → 実験評価 → 運用引継ぎです。新技術は[Radar](radar.md)、出典・日付は[根拠](evidence.md)を参照します。

## 検証の流れ

候補収集 → 一次資料照合 → 課題・根拠・用途・owner確認 → 原文翻訳更新 → 構造検査 → レビューです。自動走査は候補を集め、昇格承認はしません。旧「4つのうち2つ」は関連性信号に限定します（[維持管理](maintenance.md)）。

## 自動検査の範囲

| 検査 | 確認範囲 | 保証しないこと |
|---|---|---|
| ページ鮮度 | メタ情報の日付経過 | 全主張の再確認 |
| 主張根拠 | 日付、必須項目、影響ページ、言語表示 | 出典の真実性・現場適合 |
| 翻訳ハッシュ | 対応する原文版 | 意味の正確性 |
| Strictビルド | 内部リンク・アンカー・構成 | 外部到達性・技術主張・実行成功 |

バッジだけでなく主張別の日付、再現ログ、人の確認状態を見ます。手順は[維持管理](maintenance.md)、機械可読記録は[claims.json](assets/claims.json)です。
